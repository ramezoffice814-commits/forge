# Production Go / No-Go

Roadmap Item 20 ("Production Release & Store Submission Prep"). The
explicit, gate-by-gate answer to "can Forge actually be deployed to
production or submitted to a store today" — built from
[docs/RELEASE_CANDIDATE_2.md](RELEASE_CANDIDATE_2.md) and every
document it references. **This document does not deploy anything, does
not submit anything, and does not authorize anyone else to.** Its job
is to make the current gate state impossible to misread as "ready."

## Overall status

# **NO-GO.**

Multiple auto-NO-GO conditions are currently true (listed explicitly
below, per this item's own required list) — not because of any single
catastrophic defect, but because production signing, legal approval,
and several store-submission prerequisites are genuinely outstanding
and none of them can be closed by an engineering pass alone.

## What would need to change for this to become GO

In rough dependency order:

1. A human generates and takes ownership of a real production Android
   signing key (see the human gate in
   [docs/RELEASE_CANDIDATE_2.md](RELEASE_CANDIDATE_2.md)).
2. Legal review and approval of Privacy Policy / Terms of Service
   content, plus a decision on the open items listed in
   [docs/RC1_CHECKLIST.md](RC1_CHECKLIST.md) "Human legal-review
   blockers" (age/eligibility, liability, dispute resolution,
   governing law).
3. Real brand assets (icon, splash, feature graphic) and real
   screenshots, per [docs/STORE_ASSET_REQUIREMENTS.md](STORE_ASSET_REQUIREMENTS.md)
   and the screenshot plan in
   [docs/PLAY_STORE_PREP.md](PLAY_STORE_PREP.md).
4. A hosted, publicly reachable Privacy Policy URL (requires a
   production Web deployment decision, itself gated on #2 above).
5. A Google Play developer account, completed content-rating
   questionnaire, target-audience/pricing decisions, and (separately)
   a real account-deletion implementation — see
   [docs/ACCOUNT_DELETION_DESIGN.md](ACCOUNT_DELETION_DESIGN.md).
6. ~~Confirmation that this branch's CI run — including the new
   `android-aab-build` job — is actually green, not assumed.~~ **Done**
   — PR #13's CI run confirmed all 6 jobs green (see "Real-device /
   staging / CI status" above).
7. A real Android device/emulator run and a real, interacted-with
   Windows run, to close the two platform-verification gaps this
   environment cannot close.
8. A production Supabase project, provisioned and configured per
   [docs/RELEASE_CANDIDATE_2.md](RELEASE_CANDIDATE_2.md) "Production
   Supabase readiness" and populated with the secrets inventoried in
   [docs/PRODUCTION_CONFIG.md](PRODUCTION_CONFIG.md) — none of which
   exist yet.

None of the above is performed by this document or by this item — each
is either a human decision, a credential/account this codebase has no
authority to create, or a verification step this environment cannot
perform. This document's only job is to make that list explicit and
gate-checked, not to close any of it.
